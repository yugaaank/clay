# Security policy

## Supported versions

This is an early-stage project. Security fixes are prioritized for the latest
version on the `main` branch and the latest published release. Older releases
may not receive fixes.

## Reporting a vulnerability

Please do not open a public issue, pull request, or discussion for a suspected
security vulnerability.

Use GitHub's private Security Advisory reporting flow from the repository's
**Security** tab when it is available. If private reporting is not enabled,
contact the maintainer privately through the GitHub account
[@yugaaank](https://github.com/yugaaank) and ask for a private security-reporting
channel. Do not send secrets or exploit details in a public comment.

Include, when safe:

- A short description and affected component or version.
- Reproduction steps or a minimal proof of concept.
- The impact you believe the issue has.
- Any suggested mitigation.

Please allow time for acknowledgement, investigation, and a coordinated fix
before making the report public. Do not test against systems or data that you do
not own or have permission to assess.

## Dependency and build reports

Reports about ordinary dependency updates, build failures, or missing native
packages can use the normal issue tracker unless they expose a security
vulnerability.
